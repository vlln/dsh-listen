# 前期方向：轻量 benchmark 驱动第一版

> 历史方向记录：正文保留当时候选、授权和工作顺序，不表示项目仍未实现或未选择评测集。当前状态与授权见[文档导航](../README.md)，已确认边界见[执行契约](../design/interface/0002-executable-v1.md)，实施与运行证据见[执行容器](../plans/README.md)。

来源：2026-11-03 用户明确规划。此处确认工作顺序，不等于批准实现、下载、付费调用、安装或发布，也不冻结具体技术方案。

## 产品与分发约束
工具是面向语言模型的音频特征Pipeline，封装多步提取以减少操作；不接收question，但允许Agent调受限分析参数并返回有效参数/图例。尽量易安装、默认包及依赖闭包小；模型/运行时可选，ASR支持用户配置API或本地模式，不静默下载或上传。具体设计以[可调轻量Pipeline](../design/adr/0003-portable-configurable-pipeline.md)为准。

## 顺序
1. 选择一套轻量且适合本目标的现成 benchmark，核实语料可获取性、许可、评分和运行成本。
2. 用其任务范围约束最小功能，给缺少原生音频输入的 DSH 主模型增加声音理解工具；不为追榜扩展无关功能。
3. 完成功能与必要的工程验证后，按事先锁定的配置跑一轮 benchmark，报告分域表现、失败与成本。
4. 根据测评暴露的缺口决定下一轮，不在第一版前穷举全部技术路线。

## benchmark 选择原则
- 音乐、人声、环境/其他声均有覆盖；ASR-only不能代表目标。
- 体量和评分轻量，优先可本地自动评分、答案可核对的现成测试集。
- 评测对象明确为“无原生音频输入的主模型＋音频工具”整体，不声称主模型原生获得了音频模态。
- 优先标准公开小集；若自行抽样，固定ID/种子/分层并标注“子集结果”，不与官方全量榜分数混用。
- 先阅读官方任务、样例与许可再定选；MMAU小集仅为优先核实候选，尚未选定，具体规模/可获取性待核。

## 最小评测纪律
- 可查看任务说明、开发样例搭功能，不用封存测评答案调参。
- 最终测评前锁定题目、模型、工具版本、提示词和预算；保留同一主模型的无音频基线，用于识别题目先验。
- 主报告只需总分、音乐/人声/其他声分项、失败率、调用成本/时延与代表性错例。不以前期大规模消融矩阵为开发门槛。
- 必要时补少量静音/换音频烟测，作为工程检查而非另造大型benchmark。
- 工程单测/接口烟测与最后一轮benchmark不同；仍需遵守权限、取消和音频外发约束。
