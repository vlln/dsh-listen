# ADR-0001：先比较能力，后确定后端

## 状态
历史路线清单，不是当前实施计划。用户已指定固定证据提取、无question，由Agent推理；当前以[ADR-0002](0002-extraction-stack.md)和[特征配方](../spec/0002-feature-recipe.md)为准，A/D音频问答路线不纳入首版。未执行验证。此前对话里关于“Gemini 最好”“几十行足够”“一律 16k 单声道”“生态没有任何可用方案”的说法不是本项目证据；现成插件目录并不构成质量评估。

## 候选

| 路线 | 输入→感知→回答 | 优势假设 | 风险/代价 | 必须实测 |
|---|---|---|---|---|
| A 原生音频语言模型 | 波形→音频编码器/多模态模型→问答 | 覆盖音乐、人声、环境与关系，封装简单 | 云端隐私、价格、幻觉、时间定位与长音频丢事件；本地需算力 | 无台词是否仍理解、是否读到音频、重叠声和音乐细节 |
| B 专用感知融合 | ASR + 声音事件/音频文本模型 + 音乐特征→LLM | 有结构化中间证据，可本地化、模块可测 | 多模型安装维护、误差传播、标签词表上限；节拍估计不等于懂音乐 | 比ASR单独增加了什么、是否错误拼接关系、总时延/内存 |
| C 频谱/波形视觉代理 | 带坐标的时频图→视觉模型→回答 | 可直接接入现有视觉通路，适合观察声学结构 | 音色/语言/场景语义映射不可靠；图像尺寸、窗函数、频轴造成偏差 | 在独立任务上是否真有增益，不能凭看起来有图就说会听 |
| D 混合按需工具 | A 负责语义，B/C 仅补时间/节奏/能量等证据 | 泛化与可核查性可能兼得 | 编排、费用叠加、证据冲突；过早设计会复杂化 | A 明确短板出现后，按收益再决定是否引入 |

B 中 ASR-only 作为负向能力基线：可以完成台词任务，但不能作为音乐/环境声理解的替代。候选模型家族只作检索线索：原生音频 Gemini/Qwen-Omni，本地音频语言模型；ASR Whisper/SenseVoice；事件/检索 PANNs/CLAP；音乐特征 librosa 等。每一具体 checkpoint、许可证、可用端点及硬件要求都须核实。当前不承诺某版本、云端中转或 MLX 实现可用。

## 封装边界
目标是一个感知能力，产品只呈现音频检查/问答。Host/Cordis、bundle、Agent preset、skill 是不同装配单位；最终工具在 Agent 可见范围注册，依赖宿主权限服务。此处不因“只有一个工具”先锁定无配置页，也不造新 Agent 产品。

## 预处理约束
- 原始音频保留 hash、采样率、声道；解码失败先报错，不偷偷更换输入。
- 模型强制格式与主动有损处理分开记录。16k Nyquist 上限为8kHz；降采样后无法恢复原先更高频内容。
- 单声道折叠会丢失空间差异，反相声道还可能相消；立体声任务不能拿折叠后的结果评判原声。
- 不默认去噪、响度归一、VAD 丢静音：这些操作会改变环境、动态或事件边界。分别做消融。
- 分窗保留绝对时间偏移和重叠；跨窗关系不能仅凭摘要补造。

## 选型原则
原先先多路线实验后开发的建议已被[当前方向](../direction.md)替代：先轻量benchmark约束任务、设计固定提取功能、必要工程验证，功能完成后跑一轮测评。早期实验协议只作方法储备，不是开工前置。

## 验证
未执行。协议接通、原始音频依赖检查、音乐/人声/环境分项成绩、切窗/声道消融与失败记录齐备之前，不得将本 ADR 标为 proposed/accepted，也不得承诺实现规模。
