# 愿景

## 业务目标
让 DSH Agent 像调用图像理解一样，按需检查一段声音并回答关于可听内容的问题。音乐、人声、环境与其他声音和它们的混合都是一等输入，不以“有台词”作为成功前提。

用户不必启动视频、听写、内容创作工作流。ASR、特征提取、频谱和音频模型只是候选技术，不定义产品意图。

## 用户范围
需要 Agent 理解给定音频的 DSH 使用者；初期以提供文件或附件、明确发起分析为边界，不隐式监听麦克风或系统音频。

## 成功标准
能对可听事件、音乐属性、人声内容与可听表达特征（语速、音高、强弱等）、变化与时间关系作有根据的回答；不确定时明确说不能判断。区别“听到了什么”与“推测场景是什么”。准确率、拒答和时延须分别由实验检验，不以“API 请求成功”替代理解。

## 非目标
无 TTS、语音输入、播放器、音频编辑制作、视频分析、独立工作站、歌曲版权库或说话人身份识别。不保证辨认歌名、作曲家、精确乐器型号、个人身份、心理/健康状态；不将声学表达推断为已证实的内在情绪。

## 约束
单一能力不等于必须单一模型或零设置 UI；底层实现可组合，但不带无关业务。先证明感知能力，再决定封装与配置方式。
