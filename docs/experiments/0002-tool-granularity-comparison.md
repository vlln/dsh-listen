# 工具封装粒度对照（规划，未执行）

来源：用户指出正交特征可拆工具或合为一体，最终封装粒度应由对照实验选择；单listen不再是既定结论。上游：[Pipeline](../adr/0003-portable-configurable-pipeline.md)。不增加特征/后端大规模穷举，不授权实现或运行。

## 1. 比较什么
只改变Agent可见工具面，底层解码、提取器、参数含义、结果字段、权限与缓存实现共用。内部模块划分、npm安装分包、模型按需下载与Agent工具数量是不同维度，不捆绑选择。

| 方案 | 可见面候选（名称未定） | 要检验的取舍 |
|---|---|---|
| A 聚合 | listen(source,range,features,analysis_params) | 调用少、证据一起返回；参数复杂、可能过量提取/返回 |
| B 正交拆分 | audio_signal / audio_transcript / audio_events，共同source/range | 选择明确、独立失败/按需成本；工具数/轮次增加、Agent可能漏用 |
| C 混合（第二步才考虑） | 概览入口＋专业细查工具 | 易起步与精细控制；重复能力/路由/缓存复杂 |

先A/B，只有结果显示确有互补需要才加C，不先为每个标量造一个工具。signal中图像与统计是否也拆开，留作后续有证据的设计问题。

## 2. 公平控制
- 同一benchmark、主模型/输入模态/设置、特征能力、后端、解码、数值参数、图像质量、可用输出总量与权限；各方案只注册其工具，不同时向Agent展示另一方案。
- 每个工具相同的特征解释、单位与局限；记录工具schema token差异而非掩盖其开销。A/B都允许自主多轮、缩窗和调参，不把B预先指定完美顺序。
- 主比较采用相同底层资源预算（每提取器处理秒数、模型/API请求/费用上限）及相同Agent总推理/输出预算。不能简单设同样工具调用数作为唯一公平预算：A一次可做三项，B完成三项至少三次。调用数本身是结果指标；仅设宽松防死循环上限并披露是否触发。
- 同一输入/参数的组件结果在不改变上下文的情况下可共享受控缓存或预计算，避免随机提取器差异。缓存按方案隔离命中状态，不让后跑方案免费继承先跑暖缓存；分别报告冷/暖成本或固定一种策略。
- 总输出预算匹配规则事先冻结：两方案使用相同组件截断/图像策略；可见总量上限一致，不额外给一方案特征。不强行令实际轨迹产生相同证据：是否正确选择特征正是被测能力。

## 3. 评估与选择
- 主指标：benchmark正确率及音乐/人声/其他声音分项。
- 交互：工具选择错误、参数无效、遗漏有用特征、无效重复、完成率、证据引用与无法判断。
- 成本：Agent token（含schema和工具结果）、工具调用数、实际提取/API数、缓存命中、延迟和费用。
- 按同素材配对比较，报告逐题胜负/差异；固定或记录随机种子，关键差异可在开发样本有限复核，避免小样本宣布普适冠军。代价近似且效果差异不确定时优先简单维护的面，不为微小分数过拟合。
- 选型在开发/验证区完成。正式封存测试仍在工具面/模型/预算冻结后跑一轮；如果正式阶段同时报告A/B，须预注册并完整报告，不能看测试赢家再回改功能。

## 4. 当前结论
无胜者。保持共享、可组合提取器作为实现边界，Agent可见包装以薄适配候选设计，不开发通用插件框架。待benchmark与提取栈收敛后再落实最小A/B对照；这一规划不使早期283次多路线协议重新成为前置。
